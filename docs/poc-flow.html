blastwall

End-to-end lab validation for the identity, policy, rollout, and proof path.

Overview Demo Lab Exercise Source Flow

This lab flow is the logistics test for the recorded demo. It is written for Calabi, my nested-KVM lab for modeling disconnected OpenShift and support-service boundaries. Calabi is the validation environment, not a Blastwall dependency; the same pattern applies to any IdM-enrolled RHEL lab with a bastion-like control point and a managed endpoint.

The flow configures IdM, validates the read-side gate with eigenstate.ipa, builds a policy RPM, deploys it, and proves AF_ALG, BPF, packet_socket, userns, and self-protection denials from a mapped automation identity on the Calabi lab target mirror-registry.workshop.lan, then reads the target audit log for SELinux evidence.

Execution Boundary

Run these playbooks on bastion-01, not directly from the workstation. Stage the poc-calabi/ directory to a bastion-local path before execution.

Inputs

Provide IdM admin credentials through the environment. The automation user password is optional and only needed when the lab path requires it.

export IPA_ADMIN_PASSWORD='...'
export BLASTWALL_AUTO_PASSWORD='...'

Run Order

ansible-playbook 00-preflight.yml
ansible-playbook 10-configure-idm.yml
ansible-playbook 15-validate-idm-with-eigenstate.yml
ansible-playbook 20-build-policy-rpm.yml
ansible-playbook 30-deploy-and-test.yml
ansible-playbook 35-test-self-protection.yml

Expected Result

  • svc-ansible-runner can SSH to automation-endpoint.
  • id -Z returns blastwall_u:blastwall_r:blastwall_t:s0 or the public alias.
  • sudo -n /usr/bin/id -u returns 0.
  • The AF_ALG/authencesn probe prints BLOCKED.
  • The BPF probe prints BLOCKED for BPF_MAP_CREATE and BPF_PROG_LOAD.
  • The packet_socket probe prints BLOCKED for AF_PACKET socket creation.
  • The userns probe prints BLOCKED for unshare(CLONE_NEWUSER).
  • The self-protection play temporarily exposes /usr/sbin/semodule through sudo, then SELinux denies execution from blastwall_t.
  • A target-side audit-log query shows SELinux denial evidence for blastwall_t.

Lab Scope

Full proof path

Use this when the question is not only whether the denial works, but whether the rollout model is visible, repeatable, and auditable.
