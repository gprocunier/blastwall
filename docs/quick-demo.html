Blastwall Documentation

blastwall

A short path through the Blastwall argument: install the host policy, map the automation identity, then prove the session starts constrained.

Overview Demo Source PoC Flow

This is the shortest version of the idea. I want a managed endpoint to prove three things before I trust it for privileged automation: the local policy is installed, IdM maps the automation identity into the confined SELinux user, and AAP can see enough policy state to fail closed before it runs.

Managed Host Setup

Install the local SELinux policy on each managed RHEL host that should accept the confined automation identity.

sudo make -C policy install
sudo install -D -m 0644 \
  policy/contexts/blastwall_u \
  /etc/selinux/targeted/contexts/users/blastwall_u
sudo semanage user -a -R blastwall_r -r s0 blastwall_u

IdM Objects

Create the automation group, managed-host group, HBAC rule, sudo rule, and SELinux user map described by the IdM object model. Apply the equivalent FreeIPA module or ipa CLI workflow from a host with an admin ticket.

idm/bootstrap-blastwall.yml
poc-calabi/10-configure-idm.yml

AAP Inventory And Gate

Sync inventory from the eigenstate.ipa inventory source, then run the preflight before any mutation job.

inventory/blastwall-idm.yml
playbooks/preflight.yml

Verification

Run the managed-host verification playbook. The expected result is a confined SELinux context and blocked AF_ALG/authencesn, BPF, packet_socket, userns, and io_uring probes on the automation endpoint. The io_uring probe can report SKIP on older kernels where the SELinux object class does not exist.

playbooks/verify-managed-host.yml
